# Архитектура интерфейса LIGHT FORGE

LIGHT FORGE использует три уже работающих режима: каталог и поиск, рабочий проект RFQ, инженерная композиция. Переход от каталожной модели к проекту создаёт новый снимок и переносит только подтверждённые характеристики выбранного артикула. Изображение для поиска и производственные референсы имеют разные задачи.

| Раздел | Вход | Источник данных |
| --- | --- | --- |
| Рабочий стол | `/dashboard` | Последний сохранённый проект этого браузера и доступные действия |
| AI Visual Search | `/search` | Каталог производителя, локальный индекс при наличии, ручные источники, Gemini по согласию |
| Lighting Configurator | `/#project-heading` | Текущие параметры модели в Quick RFQ. Самостоятельный мастер запланирован |
| 3D Studio | `/geometry` | Инженерная композиция, положение XYZ, крепления, монтажные уровни |
| Manufacturing RFQ | `/` | Проект, исходные фото, документ и тело запроса |
| Projects & Library | `/projects` | Локальные проекты IndexedDB. Архивы и существующие действия остаются в редакторе |
| Settings | `/settings` | Тема браузера и фактическая доступность источников |

Рабочие редакторы открывают другой раздел в новой вкладке, чтобы не потерять текущую форму или сцену. Переходы из рабочих страниц библиотеки ведут к существующему загрузчику снимка по `rfqProject`. Сохраняемые проекты остаются доступны в старой библиотеке и новом разделе. На телефоне меню открывается как модальный диалог с возвратом фокуса. История браузера остаётся доступной.

Профессиональные ориентиры: панель свойств и список объектов в CAD, раздельные режимы сборки и просмотра, единый источник данных для проекта и документа. Список объектов и инструменты моделирования должны показывать реальную геометрию и степень подтверждения. Схемы и внешний вид других приложений не копируются.
