# Архитектура LIGHT FORGE

Один Next.js App Router проект на TypeScript. Zod описывает общие входы и выходы. Его схемы доступны и браузеру, и серверу. Серверный HTTP API вызывает те же чистые функции, которые Antigravity может использовать для быстрого локального предпросмотра. OpenAPI 3.1 создаётся из общих схем.

| Путь | Ответственность | Владелец |
|---|---|---|
| `src/domain/` | Проект, компоненты, размеры, происхождение значения, материалы, отделка, электрика и MYLINE | Codex |
| `src/geometry/` | Валидация композиций, 3D-координаты, геометрия, расчёт длин, примеры | Codex |
| `src/storage/` | Интерфейс хранилища и реализация IndexedDB | Codex |
| `src/app/api/` | HTTP endpoints Next.js | Codex |
| `src/ui/`, UI-маршруты Next.js | Русский интерфейс, формы, React Three Fiber, предпросмотр | Antigravity |
| `tests/`, `openapi.yaml` | Проверки расчётов, сохранения, ответов и контрактов | Codex, UI-тесты в отдельных файлах от Antigravity |

## Источник размеров и изображений

`Project` задаёт комплектацию и производственные требования. Каждый `Component` имеет постоянный идентификатор. Экземпляры в `Composition.elements` связываются по `productComponentId`. Для проекта с композицией геометрические размеры следует получать из `resolveComposition` и переиспользовать в PDF и 3D. Значения редактора, высоты по установке и габаритный размер — разные поля. Адаптер MYLINE переносит известные габариты из спецификации в геометрию как оболочку.

`CompositionStore` хранит в IndexedDB целый снимок композиции по ID, поддерживает переносимый JSON и проверяет схему при чтении и записи. Для синхронизации между устройствами можно реализовать тот же интерфейс поверх Supabase после появления требований к аутентификации и доступу. Переход потребует формата версий и разрешения конфликтов. Для фото в Quick RFQ контракт предусматривает метаданные в проекте и оригиналы как Blob по ID.

## Изоляция интерфейса

Математика геометрии импортирует только общие схемы. Антигравити использует результаты расчёта в React Three Fiber и задаёт обновления через общие типы. Подготовленные формы — кольцо, круговая дуга, прямой профиль и габаритная оболочка. Позже CAD-движок сможет принимать те же параметры в подходящих форматах. Текущая реализация выводит численные результаты и тип представления.
