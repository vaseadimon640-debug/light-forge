# LIGHT FORGE · работа Codex и Antigravity

- Один репозиторий. Для каждой задачи заведите отдельную ветку или worktree от согласованного коммита. Изменения объединяются через PR. Перед объединением проверьте конфликты, типы, тесты, сборку, совместимость API и реальные сценарии.
- Codex ведёт `src/domain/`, `src/geometry/`, `src/storage/`, `src/app/api/`, серверное хранение и RFQ/CAD. Он публикует общий контракт и отвечает за интеграцию.
- Antigravity ведёт `src/ui/`, `src/app/page.tsx`, `src/app/layout.tsx` и визуальные сценарии. Изменение общей схемы, инфраструктуры или API согласуется отдельной задачей. Codex подключает необходимые общие точки входа с её ревью.
- Все длины внутри системы в миллиметрах. Различайте источник данных, известную геометрию, оценку и неизвестное. Числовые значения из MYLINE — данные пользователя. Оценка по фото остаётся оценкой. Сохраняйте введённое вручную значение до явного согласия на изменение.
- Материал детали, отделка и цвет — отдельные поля. Solid brass и genuine leather самостоятельны. Условия о допустимых заменах формулируются явно. Требование Strict Materials — замены только с письменного согласия.
- Используйте одну каноническую схему для данных формы, RFQ и геометрии. Размеры корпуса, положение его нижней точки, положение крепления, путь подвеса и припуск имеют разные семантики.
- Любые образцы, концепты и чертежи показывают уровень достоверности. Для производства нужны подтверждённые данные и инженерное согласование. Подробности в [GEOMETRY.md](GEOMETRY.md).
- Сохраняйте оригиналы загруженных фотографий. Отсутствующие цены, сертификаты, свойства комплектующих и размеры оставляйте пустыми или явно отправляйте на подтверждение фабрике.
- Подключайте платные сервисы и внешние AI API после явного согласования расходов. Базовый ручной сценарий работает автономно.
- При изменении Zod-схемы выполните `npm run openapi`. Для каждого PR запустите `npm run typecheck`, `npm test` и `npm run build`.
